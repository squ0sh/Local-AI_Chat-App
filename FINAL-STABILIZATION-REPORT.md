# Final Stabilization Report

## Executive summary

This pass treated the current feature set as fixed and concentrated on release
trust, security boundaries, failure behavior, test determinism, and small
low-risk extractions. It did not rewrite the server, replace the stack, add a
cloud dependency, or redesign the working UI.

The most serious release flaw was confirmed and fixed: consumer launchers used
the absence of the **private** signing key to silently enable unsigned mode.
Signed release mode is now the default, requires only public verification
material, and fails closed. Unsigned operation requires the explicit
`CAPSULE_DEV_MODE=1` developer opt-in.

## Scope audited

- Unix and Windows portable launchers and runtime restoration
- Capsule manifest generation, signing, verification, repair, and CI checks
- Local/Remote authentication, browser origin handling, and multi-user state
- Local Ollama and owner cloud-provider routing
- Agent file, command, git, approval, memory, cancellation, and web tools
- MCP process registration, environment inheritance, framing, and lifecycle
- Research, speech temporary files, chat storage, Vault, rate limiting, and
  request/body limits
- Existing unit/integration tests and safe modularization seams

## Release integrity and signing

### Fixed

- Removed automatic `CAPSULE_ALLOW_UNSIGNED=1` from both launchers.
- Added an explicit release/dev trust-mode helper; the legacy unsigned variable
  is ignored.
- Added a launcher preflight that verifies or safely restores missing files
  before `server.mjs` runs.
- Server startup now refuses missing, unsigned, invalidly signed, incomplete,
  modified, or malformed release state.
- Missing/corrupt manifests are never regenerated by repair.
- Runtime web regeneration is developer-only and always unsigned.
- Runtime code no longer discovers or opens the private signing key.
- Expanded coverage to imported agent/MCP/user modules, tools, hooks, tests,
  cloud files, documentation, and runtime metadata.
- Schema v2 signatures bind normalized mode and embedded repair content as well
  as path, byte count, and file hash.
- Added exact coverage, duplicate, schema, algorithm, SHA-256, size, mode,
  embedded-content, manifest-size, traversal, and symlink validation.
- Repair uses bounded decompression and safe permissions.
- Signing refuses stale, incomplete, or older-schema manifests and writes
  atomically.
- Public-key fingerprints now hash canonical SPKI DER instead of PEM text.
- The pre-commit hook requires an explicitly staged manifest rather than
  invoking private-key-capable code automatically.

### Trust boundary

The signed manifest detects partial modification after a trusted acquisition.
It does not independently authenticate a completely replaced package because
the public key, launcher, verifier, and manifest ship together. Release
fingerprints/checksums must be published through an external trusted channel
(for example a signed release page). OS code signing or externally signed
release artifacts remain recommended for stronger provenance.

## Security hardening

### Local, Remote, and cloud

- Local trust now comes from the socket peer address, not a spoofable
  `Host: localhost` header.
- Browser API calls must be same-origin; wildcard CORS was removed.
- Owner controls consistently require loopback plus the origin check.
- Remote guests remain bearer/cookie authenticated, receive no owner history,
  and cannot reach model management, agent/MCP, research, Vault, cloud,
  portable, or tunnel controls.
- Remote chat and `/v1` requests are forced onto local Ollama and cannot spend
  owner cloud credentials or proxy arbitrary cloud API paths.
- Proxy response headers are now copied correctly.
- Cloud chat honors deny-egress and has bounded request timeouts.

### Agent and files

- Added a shared realpath/lstat workspace guard. Traversal, symlink components,
  `.git`, `.portable`, `node_modules`, environment, key, and Vault paths are
  rejected for agent file operations.
- Recursive search skips symlinks.
- Git uses a tested read-only grammar and disables pagers, external diff,
  textconv, config injection, output files, and mutating branch/tag/remote
  forms.
- Advertised web search/fetch tools now execute. Fetch validates every redirect,
  blocks credentials plus local/private/link-local addresses, and caps time and
  response size.
- Approval waits are abort-aware, approval IDs are random and unique, pending
  approvals are cleaned up, and disconnects cancel active loops.
- Agent inference participates in the global generation/unload lock.
- Saved agent threads include the final assistant answer and are namespaced for
  multi-user accounts.

### MCP

- Registration and direct tool calls require explicit UI approval.
- Commands are tokenized and spawned without a shell; shell operators,
  oversized arguments, malformed IDs, and wrong methods are rejected.
- MCP children receive a small environment allowlist instead of the complete
  server environment and API/auth secrets.
- Request timeouts clear pending state; malformed JSON or more than 8 MiB of
  unframed stdout terminates the child, while parsed tool results are capped at
  1 MiB; close/exit cleanup is deterministic.

### Other failure behavior

- Ollama streamed NDJSON consumes a final unterminated record.
- Ollama timeouts remain active through response-body consumption.
- Speech request overflow is reported, base64/language input is validated, and
  Whisper input/output temporary files are removed on success and error.
- `--verify-runtimes` now hashes existing Node and Ollama executables on Unix,
  macOS, and Windows before smoke testing.

## Safe modularization

The high-risk route graph and provider lifecycle remain in `server.mjs`; a
large router rewrite without characterization coverage would have increased
release risk. Four cohesive, directly tested boundaries were extracted or
strengthened instead:

- `lib/capsule-integrity.mjs` — release trust and repair
- `lib/request-security.mjs` — peer/origin trust
- `lib/workspace-safety.mjs` — filesystem confinement
- `lib/git-safety.mjs` — read-only git grammar

MCP and agent-loop behavior remain in their existing modules but now have
stricter lifecycle and boundary tests. Recommended future extractions, after
route characterization, are model catalog/reference helpers, an
`AgentThreadStore`, provider codecs, and then route factories for
models/runtime, chat/inference, agent/research, portable/networking, and
cloud/security.

## Product organization

The existing UI already maps cleanly to the desired concepts without a risky
navigation redesign:

- **Think** — chat, model inference, Deep Research, planning
- **Remember** — encrypted chat state, agent threads, Vault
- **Act** — agent files, tested git inspection, approved commands, MCP
- **Connect** — Capsule Remote, local OpenAI API, optional owner cloud providers

No sidebar or main-workflow feature was removed.

## Tests and verification

Added or expanded tests cover:

- explicit developer mode and legacy unsigned rejection
- missing/corrupt/empty/incomplete/duplicate manifests
- hostile targeted repair and symlink-parent escape
- signed mode/content tampering and stale-sign refusal
- non-mutating manifest idempotence in a temporary staged tree
- socket-peer trust and same-origin enforcement
- read-only git accepted/rejected grammar
- workspace traversal, protected paths, and symlink read/write escape
- web-fetch SSRF validation
- aborting an agent approval wait and saving the final assistant turn
- MCP missing server, normal calls, post-close behavior, secret environment
  stripping, oversized stdout, timeout, and pending cleanup

Static syntax checks, whitespace checks, the complete Node test suite, signed
manifest verification, launcher syntax, and local browser/API smoke checks are
the release gate for this branch.

The stabilization commit was reconciled with the subsequently published
v1.15 feature line before merge. The combined release manifest covers 109
files, and the expanded suite contains 226 tests spanning the original
stabilization cases plus transport, recovery, telemetry, voice, USB, memory,
MCP bridge, HTTP security, and service-installation workflows.

## Known limitations and deferred work

- The co-located trust root needs externally published provenance for
  whole-package authenticity.
- Runtime executable hashes are rechecked; individual Ollama support libraries
  are trusted from the verified archive at installation and are not re-hashed
  on every start.
- Approved shell commands and MCP servers run with the current OS account.
  Approval is not an operating-system sandbox.
- `server.mjs` remains large. Provider/tunnel/model route extraction is
  deferred until a hermetic fake-Ollama server harness covers streaming,
  disconnect, pull/resume, unload, Remote lifecycle, and provider translation.
- Voice recognition/synthesis may use browser/OS online services even when the
  conversational model is local; this is documented in the UI/README.

## Final assessment

**Mostly production-ready with documented limitations.**

The previously silent unsigned downgrade, Host-header local bypass, wildcard
browser control, Remote cloud credential exposure, repair traversal, incomplete
signed coverage, unsafe git grammar, workspace symlink escape, and MCP
environment/output weaknesses are release-blocking issues that are addressed
in this pass. Final release confidence still depends on passing the complete
verification gate and publishing an external release fingerprint/signature.
